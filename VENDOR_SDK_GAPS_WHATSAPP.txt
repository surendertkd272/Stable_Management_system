Hi team, thank you for the SDK package. We've reviewed it. The core toolkit is good — headers, C/C++ and C# samples, and working calls for set-ROI, set-emissivity, poll-temperature and RTSP all present. But there are a few technical gaps before we can start development on our hardware.

*BLOCKING (need to start):*

*1. ARM64 / Jetson build.* All the shared libraries (libVD641Module.so + dependencies) and the bundled .NET runtime are x86-64 only (Ubuntu/Debian/Deepin folders). Our edge is NVIDIA Jetson (ARM64/aarch64), so none of these will run on it. Please send aarch64 builds of the libraries, and confirm the JetPack/Ubuntu version validated.

*2. Visible↔thermal calibration (critical).* The SDK maps coordinates only within the thermal channel. We found no way to map a visible-image pixel to the matching thermal ROI point, and no calibration data for it. Our software finds the nostril/eye on the visible frame and must steer the thermal ROI — so we need the factory visible↔thermal mapping exposed in the SDK. Also: mapping accuracy (px/mm) at 3 m and 4 m, and whether re-calibration is needed after re-mounting.
